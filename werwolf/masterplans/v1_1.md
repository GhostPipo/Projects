# Masterplan: Werwolf Refactoring & MongoDB Migration

## Zielsetzung
Umbau des bestehenden Node.js/Express Backends von MySQL/lokalen Dateien auf MongoDB (NoSQL) inklusive Architektur-Trennung und Frontend-Templating. Tests und Login-System sind vorerst **ausgeschlossen**.

## Phase 1: Architektur-Trennung & Setup
- [ ] **Abhängigkeiten installieren:** `mongoose` zum Projekt hinzufügen (falls noch nicht geschehen).
- [ ] **`app.js` erstellen:** Die Express-App-Instanz, Middleware (JSON-Parsing, statische Dateien) und das grundlegende Routing aus der aktuellen `server.js` hierher auslagern. Die Datei exportiert nur die `app`.
- [ ] **`server.js` anpassen:** Darf nur noch die Umgebungsvariablen (`.env`) laden, die Verbindung zur MongoDB aufbauen (via Mongoose) und den Server (`app.listen()`) starten.
- [ ] **Altlasten markieren:** Die bestehenden SQL/File-basierten Logiken (z.B. in `migrate.js` oder im `database/` Ordner) vorerst ignorieren oder als "deprecated" markieren.

## Phase 2: NoSQL Datenmodellierung (Mongoose)
- [ ] **Ordnerstruktur anpassen:** Einen neuen Ordner `models/` erstellen.
- [ ] **`models/Game.js` erstellen:** Ein Mongoose-Schema definieren. 
  - Muss alle Spieldaten (Phase, Timer, Raumcode) enthalten.
  - Spieler müssen als Sub-Dokumente/Array direkt im Spiel-Dokument eingebettet sein (inkl. Name, Rolle, `is_alive` Status).

## Phase 3: RESTful API (CRUD Operationen)
- [ ] **Ordnerstruktur anpassen:** Einen neuen Ordner `routes/` (und optional `controllers/`) erstellen.
- [ ] **Routen definieren (in `routes/gameRoutes.js`):**
  - **POST `/api/games` (Create):** Erstellt ein neues Spiel-Dokument in MongoDB (Raumcode generieren, Standardwerte setzen) und fügt den Host als ersten Spieler hinzu.
  - **POST `/api/games/:room_code/players` (Create):** Lässt einen neuen Spieler einem bestehenden Spiel beitreten (Array-Push in MongoDB).
  - **GET `/api/games/:room_code` (Read):** Liefert das komplette Spiel-Dokument für das Polling im Frontend (`findOne`).
  - **PATCH `/api/games/:room_code` (Update):** Aktualisiert gezielt Felder (z.B. `game_phase` für Phasenwechsel oder `is_alive` für tote Spieler via `findOneAndUpdate`).
  - **DELETE `/api/games/:room_code` (Delete):** Löscht ein Spiel komplett (z.B. wenn die Lobby geschlossen wird).
- [ ] **Routen in `app.js` registrieren.**

## Phase 4: Frontend Templating (Dynamisches Befüllen)
- [ ] **`index.html` anpassen:** Das alte "innerHTML-Gefrickel" entfernen. Stattdessen native HTML5 `<template>`-Tags für die UI-Elemente (Lobby-Liste, Rollen-Karten, Aktions-Grid, Game-Over-Screen) einfügen.
- [ ] **`js/script.js` anpassen:** - Die Fetch-Aufrufe an die neuen REST-Endpunkte (`/api/games/...`) anpassen.
  - Logik schreiben, die Daten aus dem JSON-Response nimmt, die HTML-Templates klont, mit Daten befüllt und ins DOM einhängt.
